# 주가예측 딥러닝 캡스톤

Quantile 예측 기반 주가 방향 예측 + 모의투자 파이프라인.
설계 원칙과 규칙은 [`CLAUDE.md`](CLAUDE.md), 데이터 소스 검증은 [`docs/KIWOOM_VERIFY.md`](docs/KIWOOM_VERIFY.md).

주문을 내는 자동화가 스스로 켜는 동작이어야 하기 때문이다.

15:15 인 이유: 장 마감(15:30) 직전이라 종가 근처에서 체결된다 — 백테스트가
'종가 체결'을 가정하므로 비교 가능성이 가장 높다. 휴장일은 지수 일봉에 오늘 봉이
있는지로 판정한다(`is_trading_day`) — **공휴일 테이블을 만들지 않는다.**

손으로 낼 때는 그대로다:

```bash
python scripts/paper_trade.py             # 계획 확인
python scripts/paper_trade.py --execute   # 전송
python scripts/snapshot_account.py        # 계좌 기록 (읽기 전용)
```

### 하루가 도는 순서

```
15:15  daily_trade.sh    개장 확인 → paper_trade --execute
16:00  daily_collect.sh  collect → build_features → snapshot_account
```

판단은 **전일 종가** 기준이다(수집이 16:00이라 당일 데이터를 못 쓴다).
백테스트는 t 시점 데이터로 t 종가에 체결하므로 **실거래에 1세션 시차가 있다** —
15:15 실행이 이 격차를 줄이지만 없애지는 못한다. 성과가 갈리면 후보 원인이다.

**시차가 1세션보다 벌어지면 리밸런싱을 건너뛴다**(손절/익절은 현재가 기준이라 그대로).
2026-08-28 수집이 종목 2개 토큰 만료로 중단돼 `build_features` 가 안 돌았고, 8/31
매매가 8/27 예측을 봤다 — 그날은 리밸런싱 주기가 아니라 피해가 없었다. 강행은
`--ignore-stale`, 판정은 `paper_trader.data_fresh_for_rebalance`.

⚠️ **장중에 `--end-date` 없이 수집하면 오늘의 미완성 일봉이 종가 자리에 들어간다.**
16:00 자동 실행은 장 마감 뒤라 해당 없지만, 낮에 손으로 돌릴 땐 전 거래일을 지정할 것.

`--execute` 없이 돌리면 **계획만 출력하고 주문은 나가지 않는다**(기본값).
리밸런싱 주기(현재 **10거래일**, `backtest.rebalance_days`)가 아닌 날은
신규 진입 없이 손절/익절만 본다.

모든 수집은 **증분(idempotent)** — 같은 명령을 두 번 돌려도 중복 행이 생기지 않는다.

수집 결과는 `data/` 에 parquet 으로 쌓인다. 이진 파일이라 에디터로 열리지 않으니
`scripts/peek.py` 로 확인한다.

```
data/raw/{TR이름}/{종목코드}.parquet   ← API 응답 원본
data/processed/features.parquet        ← 지표·라벨까지 계산된 학습용 테이블
```

회귀 테스트: `tests/test_broker.py::TestTradeDiary`.

발표용 기록이 매일 자동으로 쌓인다.

```
outputs/paper_trading/equity.jsonl      하루 한 줄 — 총자산·현금·주식
outputs/paper_trading/holdings.jsonl    하루 × 종목 — 비중·손익률 (+ CASH 행)
outputs/paper_trading/fills.jsonl       하루 × 종목 — 체결 기준 실현손익 (ka10170)
outputs/paper_trading/performance.json  위에서 계산한 지표 + 병합된 곡선
outputs/paper_trading/baseline.json     계좌 개시 잔고 (첫날 진입 비용을 포함시키려면 필요)
```

`holdings.jsonl` 의 비중은 **총자산(NAV) 기준**이다 — `w_i = 평가금액 / 총자산`,
현금 비중 `c = 1 - Σw_i` 를 `CASH` 행으로 같이 남겨 **Σw + c = 1** 이 성립한다
(Boyd et al., *Markowitz Portfolio Construction at Seventy*, 2024, §2.1).
현금은 **잔차(총자산 - 주식평가합)** 다 — 주문가능금액은 D+2 결제 때문에 다르고
(실측 9,672,457 vs 9,174,777) 그걸 쓰면 합이 1 을 넘는다.
`tests/test_record.py` 가 이 항등식과 재실행 시 교체를 지킨다.

지표는 **백테스트와 같은 함수**(`evaluation/metrics.py`)로 계산한다 — 그래야
"백테스트 Sharpe 1.10 vs 실거래 Sharpe X" 비교가 성립한다.
관측 20일 미만이면 `reliable: false` 로 표시하고 화면이 스스로 경고한다.

**⚠️ 모의투자 수수료가 백테스트 가정의 2.3배다.** 실측: 기아 6,814,700원 매수에
23,850원 = **0.35%**. 백테스트는 편도 15.5bp(0.155%)를 가정한다. 첫날 11건에
317,358원(0.32%)이 나갔다. 실거래 성과가 백테스트보다 나쁘게 나올 구조적 이유이고,
발표에서 이 격차를 비용으로 귀속시킬 수 있다.

### 2026-09-02 운용사 관점 진단 3종 — 이 모델은 방향이 아니라 불확실성을 맞힌다

국내 운용사·기관의 검증 문법(팩터 사전검증 / 모델리스크 거버넌스 / capacity)을
파이프라인에 대입해 셋을 쟀다. **전부 읽기 전용이다 — 매매 설정을 하나도 바꾸지 않았다.**
진행 중인 실거래 기록(8/26 개시)에 영향이 없어야 했기 때문이다.

#### 폭 IC 가 방향 IC 의 12배다 — 순열검정과 같은 곳을 가리킨다

| test 구간 | 랭크 IC | t |
|---|---|---|
| 방향 (q50 → 실현수익) | 0.0236 | 3.89 |
| **폭 (q90−q10 → \|실현수익\|)** | **0.2940** | **43.79** |

같은 모델, 같은 평가 함수다. **중앙값으로 방향을 맞히는 능력보다 폭으로 변동성을
맞히는 능력이 압도적으로 크다.** 구간 커버리지도 명목 80% 대비 실측 78.6% 로
이미 잘 맞아서, CQR 보정계수가 +0.024 에 그쳤다.

> 순열검정(성과는 신호가 아니라 규칙에서 나왔다) · VSN 상위 5채널이 전부 변동성
> 계열 · 폭 IC 0.29 — **서로 독립인 세 측정이 같은 결론을 가리킨다.**
> 이 프로젝트의 정직한 주장은 "오를 종목을 고른다"가 아니라
> **"지금 판단해도 되는지를 안다"** 이다. 기권 로직을 차별점으로 잡은 설계가
> 결과적으로 모델의 실제 능력과 맞았다.

#### 보정은 주문을 바꾸지 않는다 (그래서 안전하다)

CQR 은 가법이든 승법이든 모든 폭에 같은 방향으로 작용하므로 **폭의 순서를 보존한다.**
기권 임계값은 폭 분포의 백분위라서(`resolve_abstain_threshold`) 순서만 보존되면
선택이 그대로다. 실측 확인: 보정 전후 폭 순위상관 **1.000000**, 기권 선택 **완전 동일**.
`scripts/coverage.py` 가 이걸 매번 검사한다.

#### 팩터 사전검증 — 넣지 않기로 한 근거를 실측으로 확보했다

"TFT 에 넣기 전에 단변량 IC 로 피처를 선별하자"는 제안을 **채택하지 않았다.**
이유가 측정으로 나왔다:

| | 값 |
|---|---|
| VSN 중요도 ↔ train 단변량 \|IC\| 순위상관 | **-0.03** |
| train \|IC\| ↔ test \|IC\| 순위상관 | **0.22** |

**train IC 로 고른 순서가 test 에서 유지되지 않는다(0.22).** 그 위에서 피처를
잘라내는 건 선택편향을 하나 더 얹는 일이다. 대신 **대조표**로만 쓴다.

#### VSN 의 '동적' 선택은 사실상 고정이다

창별 순위 ↔ 전역 평균 순위 일치도 **0.966**, 날짜 부트스트랩(300회) 순위 표준편차
**0.00**, 연도별 일치도 **0.99**. 재현성은 좋지만 "상황에 따라 다른 변수를 본다"는
서술은 쓸 수 없다. KCMI 가 말한 **안전 환상**을 실측으로 옮긴 자리다.

#### capacity — 이 전략은 개인 계좌 규모에서만 성립한다

실제 체결 994건에 그 시점 ADV·변동성을 붙여 제곱근 충격 모형으로 계산했다.

| 판정선 | 그 선을 넘는 운용자금 (eta=1.0 / 0.5) |
|---|---|
| 백테스트가 가정한 슬리피지(연 1.00%) | 2억 / 6억 |
| **순열검정이 잰 신호 기여분(CAGR +1.7%p)** | **4억 / 17억** |
| 백테스트 CAGR 전체(30.5%) | 1,401억 / 5,605억 |

현재 모의계좌가 1억이라 이미 같은 자릿수다. 자릿수로만 읽을 것 — eta 에 2~4배 민감하다.

⚠️ 국내 팩터투자 문헌의 "**손익분기** 운용자금"(고정비 회수 최소 규모)은 이 봇에
그대로 대입되지 않는다. 고정비가 0 이고 한국 주식 비용이 전부 비례(bps)라
**하한선은 없다.** 실제로 존재하는 건 상한(capacity)이다.

### 2026-08-31 GBDT 베이스라인 + 순열검정 — 성과의 대부분은 신호가 아니었다

이 프로젝트에서 가장 중요한 음성 결과다. 두 질문을 한 번에 물었다:
**(a) 트랜스포머를 쓸 이유가 있나** — 잘 튜닝한 트리보다 나은가.
**(b) 백테스트 Sharpe 1.63 은 정말 모델이 만든 값인가.**

#### 왜 물어야 했나

Qlib 공식 벤치마크(CSI300/Alpha158)에서는 LightGBM·XGBoost 가 Transformer·LSTM 을
모두 이긴다(Rank IC 0.047~0.051 vs 0.041~0.044). 우리 자체 진단도 같은 방향이었다 —
`rvol_20` **단일 피처**의 test 랭크 IC(0.0411)가 학습된 모델 전체(0.0237)보다 컸다.
"잘 최적화된 단순 베이스라인과의 공정한 비교가 없다"는 건 이 분야 문헌의 공통
약점이고, 우리도 그게 없었다.

**공정성을 위해 고정한 것:** 같은 패널 / 같은 날짜 기준 split / 같은 embargo /
같은 타깃 / 같은 평가 함수 / 같은 백테스트와 매매 설정 / 같은 `(code, date)` 교집합
(Phase1 은 lookback 120일이 차야 첫 예측을 내므로, 안 맞추면 GBDT 가 더 이른 구간을
덤으로 먹는다) / early stopping 도 **날짜 기준 val** (sklearn 내장은 train 을 무작위로
쪼개는데 인접일이 상관돼 있어 낙관적으로 멈춘다).

**구조상 다른 것:** Phase1 은 (120일 × 17채널) 시퀀스를 보고, GBDT 는 시점 t 의 피처 +
지정한 lag(1/5/20)만 본다. 트리는 시퀀스를 못 먹는다 — Alpha158 도 같은 방식으로
lookback 정보를 피처에 접어 넣는다. 85피처 / train 274,939행.

#### (a) 예측력은 트랜스포머가 크게 이긴다

| test 518일 | 랭크 IC | t | 십분위 스프레드 |
|---|---|---|---|
| **Phase1 트랜스포머** | **+0.0235** | **3.87** | +0.189% |
| GBDT (HistGB quantile) | +0.0043 | 0.56 | +0.213% |

GBDT 의 IC 는 **0과 구분되지 않는다**(t=0.56). Qlib 벤치마크와 반대 결과다.
시장·유니버스·피처셋이 다르니 문헌에 대한 반증까지는 아니지만, "트랜스포머를
쓸 이유가 없다"는 기본 반론에는 답이 된다.

#### (b) 그런데 백테스트는 GBDT 가 더 좋다 — 이 모순이 순열검정을 불렀다

| | CAGR | Sharpe | MDD | 연 회전율 |
|---|---|---|---|---|
| Phase1 | 31.6% | 1.63 | -10.8% | 19.8 |
| GBDT | 36.9% | 1.62 | -16.2% | 26.5 |

IC 가 0 인 신호가 IC 0.024 인 신호와 같은 Sharpe 를 낸다. 그러면 그 Sharpe 는
어디서 오는가.

#### 순열검정 — `q50` **순위만** 섞는다

폭(q90−q10)은 종목에 붙어 있으므로 기권 판단이 바뀌지 않고, 섞인 `q50` 은 자기
`[q10, q90]` 안으로 되돌려 분위 교차를 막는다. 즉 **바뀌는 것은 순서 하나뿐**이다.
나머지(기권·top_n·버퍼·리밸런싱 주기·비용)는 전부 그대로 둔다. 20회 반복.

| | 실제 Sharpe | 섞었을 때 평균 | 섞었을 때 범위 | p |
|---|---|---|---|---|
| **Phase1** | 1.63 | **1.51** | 1.13 ~ 1.88 | **0.25** |
| GBDT | 1.62 | **1.92** | 1.67 ~ 2.28 | 1.00 |

**Phase1 의 신호 기여는 Sharpe +0.12 / CAGR +1.7%p 이고 통계적으로 유의하지 않다.**
GBDT 는 **섞은 쪽이 더 좋다** — 그 신호는 잡음이 아니라 방해다.

즉 Sharpe 1.63 은 순위가 아니라 **파이프라인이 만든 값**이다. 기권(폭 기준)이
저변동성 종목만 남기고, `top_n` 20 · `exit_rank` 40 버퍼 · 10일 리밸런싱이 회전율을
눌러 비용을 연 2.5% 로 묶는다.

이건 이미 알던 것과 어긋나지 않는다 — "앙상블이 IC 를 19% 올렸는데 백테스트는
제자리"와 같은 현상이고 원인도 같다. **IC 는 전체 횡단면의 순서를 재는데 전략은
상위 20개만 산다.**

#### 이 결과를 숨기지 않는다

이 프로젝트의 주장은 "모델이 돈을 번다"가 아니라 **"어디까지가 진짜인지 검증했다"**
쪽이고, 자기 성과를 스스로 반증 시도한 기록이 그 주장의 근거다. 발표 서술은 이렇게 선다:

> 모델은 예측한다 — 랭크 IC t=3.87 이고, 같은 조건에서 GBDT 를 크게 이긴다.
> 그러나 **IC 0.025 로는 롱온리 20종목 전략에서 신호와 잡음을 가를 수 없다.**
> 백테스트 성과의 대부분은 예측이 아니라 리스크 관리에서 나왔다 — 순열검정으로 실측했다.

| | 일봉 트랙 | 60분봉 트랙 |
|---|---|---|
| 학습 구간 | 2015-03 ~ 2022-12 (7.8년) | 2025-08 ~ 2026-03 (**8개월**) |
| 학습샘플 | 260,339 | 137,386 |
| 기준선 대비 | +3.34% | **+5.75%** |
| 랭크 IC (test) | +0.0243 (t=4.00) | **+0.0599 (t=3.99)** |
| 십분위 스프레드 | +0.19% (< 왕복비용) | **+0.89% (> 왕복비용 0.31%)** |

**해상도를 7배 올리자 예측력이 2.5배가 됐다.** 십분위 스프레드가 처음으로 왕복비용을
넘었다 — 일봉 트랙이 못 넘던 선이다.

#### 그런데 절대 임계값으로는 한 건도 못 산다

첫 백테스트는 체결 **0건**이었다. 원인은 일봉 트랙과 같은 자리인데 이번엔 배수까지 쟀다:

```
모델 q50 분포   p50 -0.0018   p90 +0.0016
실제 타깃 분포  p50 +0.0010   p90 +0.0580      ← 36배 차이
매수 임계값     0.0040 (= max(설정, 왕복비용))  초과 비율 1.2%
```

분위회귀는 조건부 신호가 약하면 중앙값으로 수축한다. **`q50` 은 기대수익률이 아니라
순위 정보를 가진 점수다** — 절대 임계값과 비교하는 것 자체가 스케일 오류다.
`src/trading/CLAUDE.md` 의 "절대 임계값을 버린 이유"가 분봉에서도 그대로 성립한다.

#### 청산 규칙 스윕 — test 에서는 통과, val 에서는 전멸

진입을 순위 방식으로 바꾸고 청산 규칙만 스윕했다 (`scripts/sweep_intraday.py`,
**모의계좌 실측 비용** 왕복 0.88% 기준):

| 만료 | 익절/손절 | 보유봉 | 거래당 수익 (test) | 거래당 수익 (val) |
|---|---|---|---|---|
| 7봉(1일) | 3% / -2% | 5.9 | +0.34% | **-0.19%** |
| 35봉(5일) | 10% / -5% | 32.4 | +1.31% | **-1.63%** |
| 70봉(10일) | 10% / -5% | 57.8 | **+2.41%** (Sharpe 1.65) | **-2.15%** (Sharpe -3.36) |

**test 에서 최고인 조합이 val 에서 최악이다. 순위가 뒤집힌다.**

원인은 월별로 쪼개면 바로 보인다:

```
2026-04  IC +0.0936  t=+4.82      2026-07  IC +0.0498  t=+2.26
2026-05  IC -0.0038  t=-0.20  ←   2026-08  IC +0.0692  t=+3.23
2026-06  IC +0.0828  t=+1.41
```

5개월 중 **2026-05 한 달만** 예측력이 0 인데, 그 한 달이 val 구간의 82%(126/154봉)를
차지한다. 즉 "모델이 못 맞힌다"가 아니라 **"한 달짜리 국면에서 무너진다"** 이고,
그 한 달에 왕복 0.88% 비용이 겹치면 계좌가 녹는다.

#### 판정: 실주문으로 넘어가지 않는다

계획 단계에서 **미리 못 박은** 성공 기준으로 판정한다.

| 기준 | test | val | 판정 |
|---|---|---|---|
| 거래당 수익 > 왕복비용 × 1.5 (1.32%) | +2.41% ✅ | -2.15% ❌ | ❌ |
| 승률 > 50% | 59.5% ✅ | 24.1% ❌ | ❌ |
| 모의계좌 비용 적용 CAGR > 0 | +34.6% ✅ | -39.5% ❌ | ❌ |

**한 구간에서만 통과하는 건 통과가 아니다.** 그리고 분봉 이력이 13개월 롤링이라
walk-forward 다구간 검증이 **구조적으로 불가능**하다 — 국면이 2~3개뿐이라
"이 전략이 국면 의존적인가"를 더 이상 물을 데이터가 없다.

발표에서 이건 실패가 아니라 **결과**다: 해상도를 올리면 예측력이 오르고(IC 2.5배),
그 예측력이 처음으로 거래비용을 넘지만(십분위 스프레드 0.89% > 0.31%),
**국면 하나가 그걸 전부 되돌린다**는 것을 실측으로 보였다.

### 2026-08-27 전략 재설계 — 문헌 근거로 breadth 와 회전율을 다시 잡았다

**계기.** 최근 6개월 모의투자가 -13.29%, 같은 기간 코스피200 은 +13.47%.
"삼성전자·SK하이닉스 둘만 들고 있어도 흑자"라는 지적이 맞았다. 감이 아니라
문헌에서 축을 뽑아 144격자 x val/test x 비용2벌 = **576회 백테스트**로 검증했다.

| 문헌 | 주장 | 이 프로젝트에 적용 |
|---|---|---|
| Grinold (1989) *Fundamental Law of Active Management* | IR = IC x √breadth | 우리 IC 는 0.024. 낮은 IC 는 **종목 수**로만 만회된다 → `top_n` 스윕 |
| Gârleanu & Pedersen (2013) *JF* 68(6) | 최적 거래속도는 지평이 아니라 **알파 감쇠 대비 비용**이 정한다 | "지평 5일이니 5일마다"라는 기존 근거를 재검증 → `rebalance_days` 스윕 |
| NBIM (2018) *No-trade band rebalancing* | 무거래 밴드가 리스크를 유지한 채 회전율을 줄인다 | `exit_rank = 2 x top_n` 유지 |
| Clarke, de Silva & Thorley (2002) | 롱온리·현금보유 제약이 transfer coefficient 를 깎는다 | `exposure_scaling` on/off 스윕 |

**축별 평균 Sharpe (모의계좌 비용, val / test).** 두 구간에서 방향이 일치한 축만 바꿨다.

| 축 | 값 | val | test | 판정 |
|---|---|---|---|---|
| `top_n` | 10 / 20 / 30 / 40 | -0.19 / 0.62 / 0.81 / 0.66 | 0.63 / 0.93 / 1.00 / 1.09 | **10 은 과집중.** 20~30 채택 |
| `rebalance_days` | 5 / 10 / 20 | 0.30 / 0.51 / 0.62 | 0.72 / 0.94 / 1.07 | **5일은 과회전.** 10 채택 |
| `abstain.percentile` | 30 / 60 / 100 | 0.90 / 0.58 / -0.06 | 1.17 / 0.91 / 0.65 | 현행 30 이 이미 최적 — 유지 |
| `stop_loss` | -5% / 없음 | 0.44 / 0.51 | 0.89 / 0.94 | 차이가 표본오차 수준, MDD 는 손절이 낫다 — 유지 |
| `exposure_scaling` | on / off | 0.45 / 0.50 | 0.94 / 0.89 | **val 과 test 가 상충** — 결론 없음, 유지 |

**바꾼 값 4개.** `top_n` 10→20, `exit_rank` 20→40, `max_trades_per_day` 20→40,
`rebalance_days` 5→10. 근거는 `configs/config.yaml` 주석과

| 수익 | 5/20 | **5/20** |
| Sharpe | 8/20 | 9/20 |
| MDD | 20/20 | 20/20 |

수익률 절대값은 33% 올랐는데 **지수를 이기는 창은 하나도 안 늘었다.** 지수가 이기는
구간에서는 격차가 크고, 우리가 이기던 구간은 원래 이기고 있었기 때문이다.
최근 6개월도 -5.15% → **-9.38%** 로 나빠졌다(노출이 커진 만큼 손실도 커진다).

**결론: 롱온리·1배수·지수 미포함 조건에서 이 유니버스·이 신호로는
코스피200 을 수익률로 이길 수 없다.** 실측으로 확인된 천장은 CAGR 약 30% 다.

### 2026-08-27 모델 개선 시도 3건 — 전부 실패 (음성 결과 기록)

**진단.** 과적합이 아니라 **언더피팅**이다. in-sample 랭크 IC 조차 0.0406
(val 0.0229 / test 0.0241). 분기별로 봐도 test 안에서 붕괴가 없어 '모델이 낡았다'도 아니다.

**결정적 증거.** `rvol_20` **단일 피처**의 test 랭크 IC 가 +0.0411 로 학습된 모델
전체(+0.0237)보다 크다. 딥러닝 모델이 엑셀 한 줄짜리 정렬보다 못하다.

| 시도 | 가설 | 결과 |
|---|---|---|
| 시장대비 타깃 (`target_mode`) | 시장 공통성분이 용량을 잡아먹는다 | 기준선 개선 +3.33% (기존 +3.35%) — **무효** |
| 횡단면 피처 8종 + RevIN 우회 (`profiles.xs`) | RevIN 이 종목별 창 안에서 표준화해 '오늘 몇 등인가'를 지운다 | val IC +0.0228 → **-0.0087** — **악화** |
| 트랜스포머 + 팩터 합성 앙상블 | 두 신호 상관이 0.30 뿐이라 섞으면 낫다 | IC +19%(0.0235→0.0280)인데 **백테스트는 제자리** (val Sharpe 1.64→1.59) |

**앙상블이 IC 는 올렸는데 성과가 안 오른 이유:** 전략은 기권 통과분 중 **상위 20개만**
산다. IC 는 전체 횡단면의 순서를 재는 지표라, 개선이 중간·하위에서 나면 전략이 만질 수 없다.

**부수 확인:**
- **한국 시장엔 모멘텀이 없다.** `mom_12_1` IC train -0.0085 / test +0.0011 로 무의미.
  반전·저변동 계열만 유의하다. 문헌(코스피 전체 유니버스 모멘텀 무의미)과 일치.
- **가중치를 학습하면 깨진다.** 릿지 회귀는 test IC 가 전부 **음수**(-0.0041~-0.0075).
  부호만 train 에서 가져온 동일가중은 +0.0274. 국면이 바뀌면 팩터 간 상대 강도가 뒤집힌다.
- **아키텍처는 병목이 아니다.** 트랜스포머가 릿지를 크게 이긴다. 모델을 바꿔도 안 오른다.

**결론: OHLCV + 기술적 지표로 뽑을 수 있는 신호의 천장이 랭크 IC ≈ 0.025 다.**
이걸 넘으려면 지금 없는 데이터(뉴스·공시·컨센서스·섹터 관계)가 필요하다.
`profiles.xs` / `xs_mr` / `mktrel` 은 재현용으로 남겨둔다 — **다시 시도하지 말 것.**

### 2026-08-25 학습·백테스트 결과

**학습은 재현됐다.** 캐글 GPU 에서 기준선(무조건부 분위수) 대비 **+3.34%**,
best epoch 3 — 로컬 스윕(+3.35%)과 소수점 둘째 자리까지 일치.

**백테스트는 전략이 거래를 거의 안 했다.** 2.1년 체결 64건, 평균 노출 8.9%.
진 게 아니라 참여를 안 했다. 원인은 기권 로직이 아니라 **절대 임계값**이었다 —
모델 예측 중앙값(-0.15%)이 실제 평균(+0.80%)과 어긋나 매수 임계값(+0.40%)에
구조적으로 못 닿았다. 상세는 [`src/trading/CLAUDE.md`](src/trading/CLAUDE.md).

→ 매매 신호를 **횡단면 순위**로 전환했다. 전략이 살아났다:
체결 64 → **1,247**, 평균 노출 8.9% → **66.5%**, Sharpe 0.14 → **0.88**,
CAGR 0.03% → **12.28%**.

### 모델은 방향을 배웠다

```
랭크 IC  +0.0243   t = +4.00   515일   양수비율 55.7%
```

IC 0.024는 주식 횡단면 예측에서 정상 범위(0.02~0.05)이고 **t=4.0이면 통계적으로 명확하다.**
피처 중요도가 변동성 계열에 몰려 있는 건 사실이지만 방향 정보도 실제로 들어 있었다.

### 그런데도 매수후보유(CAGR 49.2%)에 진다 — 원인 셋

| # | 원인 | 근거 |

**리스크는 절반을 졌는데 수익은 4분의 1만 가져왔다.**
기권 필터가 신뢰구간이 좁은 = 저변동성 종목만 남기는데, CAGR 49% 폭등장에서
저변동성은 구조적으로 뒤처진다.

→ **이력 버퍼 + 최소 거래폭**으로 회전율을 낮췄고, 비용·보유일수·차단사유를
실측으로 남기게 했다. `python scripts/backtest.py --compare` 가 규칙 5가지를

## 클라우드 GPU 학습

맥북(MPS)은 epoch당 약 19분이라 50 epoch에 16시간이 걸린다. 학습만 외부 GPU로 옮긴다.
**수집은 로컬에서만 한다** — 키움 API는 등록된 IP에서만 호출되기 때문이다.


그 다음 노트북을 연다. **Kaggle 권장** — 주당 30시간, 세션 12시간이라 Colab 무료보다 길다.

- 진행 상황 = 이 README 의 상태표. 뭔가 끝내면 여기 표를 고친다
- 검증·실험 결과 = `docs/` 와 `outputs/reports/`
- 작업 단위로 커밋. 커밋 메시지가 곧 작업 이력이다

## 안전장치

- `KIWOOM_ENV=live` 는 `src/utils/config.py` 에서 예외를 던진다. 실전투자 경로 없음.
  `PaperBroker` 가 생성 시점에 한 번 더 확인한다 (2중 방어).
- `.env` 는 gitignore. `.env.example` 에는 키 **이름만** 둔다.
- 매매 신호는 `src/trading/signal.py` 하나만 사용 — 백테스트/모의투자가 같은 코드를 공유한다.
  추론도 `src/models/inference.py` 하나만 쓴다.
- `scripts/paper_trade.py` 는 **기본이 dry-run**. `--execute` 를 붙여야 주문이 나간다.
- 대시보드는 **읽기 전용**이다. 화면에서 주문을 낼 수 없고, 기본 바인딩은 127.0.0.1 이다.
- 패널 신선도 문턱이 **둘**이다. 영업일 **3일** 이상 낡으면 실주문 자체를 막고,
  **1일**만 밀려도(= 세션 하나를 놓쳤다) 리밸런싱을 건너뛴다 — 손절/익절은 현재가로
  판정하므로 그대로 나간다. 둘 다 `--ignore-stale` 로만 강행된다.
