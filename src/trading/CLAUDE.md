# src/trading — 매매 신호·리스크·모의투자 실행

> 루트 [`CLAUDE.md`](../../CLAUDE.md)의 절대 규칙이 우선한다.
> **모의투자 전용이다. 실전매매가 아니다.**

## 자동매매 판단 기준

모델의 Quantile 출력(10/50/90분위)을 아래 **순서대로** 규칙화해 매매 신호로 변환한다.

```
1. [기권 판단] 90분위 - 10분위 신뢰구간 폭이 임계값보다 넓으면 → 거래 안 함, 관망
2. [방향 판단] `direction.mode` 가 정한다
   - cross_sectional (기본): 기권 통과분끼리 q50 순위 → 상위 top_n 매수
     · **이력 버퍼**: 보유 중이면 exit_rank 밖으로 나갈 때만 판다
   - absolute: q50 이 고정 임계값 초과 시 매수. 임계값은 왕복비용 위로 강제
3. [포지션 사이징] 확신할수록(구간이 좁을수록) 크게. 균등 배분 아님
   - 선택된 종목들 사이에서 **정규화**해 목표 노출을 채운다(rank_normalized)
   - `exposure_scaling`: 생존 후보가 적으면 총 노출을 줄인다 → "얼마나 쉬는가"
4. [리스크 오버레이] 최종 주문 전 반드시 아래 안전장치를 적용
   - 개별 종목 보유비중 상한 (예: 전체 자산의 10% 이내)
   - 손절매(stop-loss): 진입가 대비 -N% 하락 시 강제 청산
   - 일일 최대 거래횟수 제한 (과적합 신호로 인한 과도거래 방지)
5. 최종 결정된 주문을 키움 REST API 모의투자 매수/매도 엔드포인트로 전송
```

## 절대 임계값을 버린 이유 (2026-08-25)

`absolute` 는 **예측 수준(level)이 국면과 어긋나면 그대로 무너진다.**
test 구간 실측:

| | |
|---|---|
| 모델 5일 예측 중앙값 | **-0.15%** |
| 같은 구간 실제 평균 | **약 +0.80%** |
| 매수 임계값 | +0.40% — 예측 90분위(+0.27%)보다 높다 |
| 결과 | 2.1년 동안 체결 **64건**, 평균 노출 8.9%. 진 게 아니라 참여를 안 했다 |

train 구간이 2022년 하락장을 포함해 끝나 모델이 그 시기의 드리프트를 학습했다.
**순위 방식은 모든 종목에 공통으로 낀 편차가 상쇄되므로 이 문제를 안 받는다.**
`tests/test_signal.py::test_level_shift_does_not_change_selection` 이 그 성질을 지킨다.

기권 로직은 그대로다 — 폭으로 거른 뒤 살아남은 것들만 순위를 매긴다.
**판단 순서(기권 → 방향)는 안 바뀌었다.**

## 타점 탐지 모드 (2026-08-27, 60분봉 트랙)

**같은 `absolute` 를 목적을 바꿔 되살린 것이다.** 위에서 폐기한 이유는
"포트폴리오를 늘 채워야 하는데 임계값에 못 닿았다"였다. 타점 탐지에서는
**못 닿으면 대기가 정답**이라 그 실패가 실패가 아니다.

새 코드는 거의 없다 — `signal.py` 는 **수정하지 않았다**. 조합만 바꿨다:

| 스위치 | 값 | 뜻 |
|---|---|---|
| `direction.mode` | `absolute` | 순위가 아니라 조건. 종목별로 독립 판단 |
| `backtest.hold_until_exit` | `true` | **신호가 없다고 팔지 않는다** |
| `backtest.rebalance_days` | `1` | 매 봉 탐지 (판단은 자주, 진입은 드물게) |
| `risk.max_holding_bars` | `7` | 예측 지평이 지나면 그 예측은 만료 |

진입 조건 (전부 충족):
1. 기권 통과 — `(q90-q10) ≤ 임계`
2. `q50 ≥ max(long_threshold, 왕복비용)` — `generate_signal()` 이 이미 강제한다
3. 미보유 + 리스크 오버레이 통과

청산 조건 (하나라도): 익절 / 손절 / **보유만료**. 그 외에는 아무것도 하지 않는다.
노출 0% 가 며칠 이어지는 것이 정상 동작이다.

⚠️ **보유분을 재조정하지 않는다.** 매 봉 비중을 다시 맞추면 타점과 무관한 잔챙이
거래가 쌓이는데, 그 비용이 이 트랙에서 이기려는 대상이다.
`backtest.py` 가 `hold_until_exit` 일 때 보유 종목의 BUY 신호를 건너뛴다.

⚠️ `apply_risk_overlay(liquidate_unsignaled=False)` 로 불러야 한다. True 로 두면
"곧 팔 종목"을 보유로 세지 않아 총 익스포저 계산이 무너진다(아래 §총 익스포저).

## 이력(hysteresis) 버퍼 — 회전율이 성과를 먹는다

순위 전환으로 전략은 살아났지만(체결 64 → 1,247, 노출 8.9% → 66.5%, Sharpe 0.14 → 0.88)
매수후보유에 졌다. 원인의 절반이 **거래비용**이었다.

| | |
|---|---|
| 연 회전율 | **46.9** (5일마다 거의 전량 교체) |
| 십분위 스프레드 | +0.19% (t=1.07) |
| 왕복비용 | **0.31%** ← 스프레드보다 크다 |

**상하위 수익차가 왕복비용을 못 넘으므로 회전할수록 잃는다.**
신호를 더 좋게 만들 수 없다면 비용을 신호 밑으로 낮춰야 한다.

```yaml
top_n: 10        # 살 때
exit_rank: 20    # 팔 때 — 이 순위 밖으로 나갈 때만. top_n 과 같으면 버퍼 없음
```

11등이 된 종목을 파는 건 정보가 아니라 노이즈에 반응하는 것이다.
합성 검증: 신규 편입이 리밸런싱당 5.69 → 2.51개(-56%),
전 구간 백테스트에서 회전율 70.4 → 53.9, 실지불 비용 10.89% → 8.34%.

`generate_signals(preds, cfg, max_width=..., held=set(...))` 로 보유분을 넘긴다.
모의투자도 자기 보유분을 넣는다 — **같은 함수다**.

⚠️ **기권은 버퍼보다 우선한다.** 보유 중이어도 신뢰구간이 넓어지면 판다.
판단 순서에서 기권이 맨 앞이라는 원칙에 예외를 두지 않는다.

**최소 거래폭**(`sizing.min_trade_weight`)이 재정규화로 생기는 잔챙이 거래를 막는다.
`should_trade()` 가 판단하고, **전량 청산은 밴드와 무관하게 항상 통과**한다 —
밴드가 청산을 막으면 손절이 무력화된다
(`tests/test_backtest.py::TestShouldTrade`).

⚠️ `should_trade` / `one_way_cost` 의 정본은 **`signal.py`** 다. 백테스트가
`from src.evaluation.backtest import should_trade` 로도 열리지만 그건 재수출이고,
모의투자와 같은 구현을 보장하기 위해 한 곳에만 둔다.

## 총 익스포저 계산의 함정

`apply_risk_overlay` 의 `liquidate_unsignaled` 를 틀리게 잡으면 **곧 팔 종목을
'보유 중'으로 세어 신규 진입 비중을 깎는다.** 실측: 9종목 교체 매매에서
목표 0.81 이 0.09 로 잘렸다(9배). 매 회차 종목을 갈아타는 순위 방식에서 특히 치명적이다.

백테스트는 신호 없는 보유분을 청산하므로 `True` 가 맞다.
`tests/test_risk.py::test_rotation_does_not_shrink_new_positions` 가 회귀를 막는다.

⚠️ `top_n × max_position_pct` 가 `max_gross_exposure` 보다 작으면
노출 상한이 아니라 **종목 상한이 총 노출을 결정한다.** 설정 바꿀 때 같이 확인할 것.

## 모의투자 실행 — 비중을 수량으로 바꾸는 일만 한다

`paper_trader.py` 가 새로 하는 판단은 **하나도 없다.** 기권·순위·사이징은
`signal.py`, 손절·한도는 `risk.py`, 예측은 `models/inference.py` 가 이미 끝냈다.
여기 규칙을 덧대면 백테스트에서 검증한 숫자가 실거래에서 재현되지 않는다.

```
collect → build_features → predict_recent → generate_signals → apply_risk_overlay
                                          └── 백테스트와 같은 함수 ──┘
                                                    ↓
                                       비중 → 정수 주 → PaperBroker
```

백테스트에 없던 **체결 제약 셋**만 여기서 처리한다. 판단이 아니라 제약이라
등가성을 깨지 않는다.

| 제약 | 처리 |
|---|---|
| 정수 주 단위 | `int(비중 × 총자산 ÷ 가격)`. 1주 미만이면 못 산다 |
| 주문가능금액 | 매도를 먼저 보내고 **계좌를 다시 조회**한 금액으로 매수한다 |
| 매도가능수량 | 미결제분은 브로커가 거부한다 — 그 전에 우리가 줄인다 |

**매도 대금이 언제 쓸 수 있게 되는지 추정하지 않는다.** 계좌 설정마다 다르고,
틀리면 주문 거부이거나 (운 나쁘면) 예상보다 많이 사게 된다. 다시 조회하면 끝난다.

### 기권 임계값은 '최근 구간' 분포로 잡는다

모의투자는 오늘 하루치 예측만 있으면 될 것 같지만 아니다. 임계값이
**폭 분포의 백분위**라서 오늘 하루만 보면 시장 전체가 불확실한 날에도
"그날 기준 상위 30%"가 그대로 통과한다 — 기권 로직이 '언제 쉬는가'를 판단하지 못한다.

`predict_recent(days=90)` 이 최근 구간을 예측하고, 그중 **마지막 날**만 판단 대상이 된다.
백테스트는 test 구간 전체 분포를 쓴다 — 같은 함수(`resolve_abstain_threshold`)에
입력만 다르다.

실측(2026-08-25): 최근 90일 기준 임계 폭 0.2022 / 기권률 66% 였고,
test 구간 2.1년 기준으로는 0.1213 / 71% 였다. **임계값은 절대값이 아니라 상대값이다.**

### 상태 파일에 무엇을 두지 않는가

`outputs/paper_trading/state.json` 에는 **진입일과 마지막 리밸런싱일뿐**이다.
보유수량·매입가는 브로커가 정본이다 — 로컬에 복제하면 언젠가 어긋나고,
어긋난 쪽으로 주문이 나간다. 손절 기준가도 브로커의 매입단가를 쓰므로
상태 파일이 날아가도 손절은 계속 동작한다.

### 리밸런싱 주기 사이에도 손절은 본다

주기(5일)가 아닌 날은 `rebalancing=False` 로 돌아 신규 진입·비중 조정을 하지 않고
`apply_risk_overlay` 의 강제 청산만 적용한다. 백테스트는 리밸런싱 시점에만 손절을
평가하므로 **실거래 쪽이 조금 더 보수적**이다 — 이 차이는 의도한 것이다.

⚠️ 이때 `liquidate_unsignaled=False` 여야 한다. True 로 두면 "신호가 없다"는 이유로
보유분 전량 청산이 나간다.

## 안전장치 — 주문은 되돌릴 수 없다

| 층 | 무엇 |
|---|---|
| 설정 | `KIWOOM_ENV=live` → `config.py` 가 예외 |
| 브로커 | `PaperBroker.__init__` 이 `is_mock` 재확인 |
| CLI | `scripts/paper_trade.py` 는 **기본이 dry-run**. `--execute` 필요 |
| 데이터 | 패널이 영업일 3일 이상 낡으면 실주문 차단 |
| 화면 | 대시보드는 읽기 전용 — 버튼으로 주문이 나가는 경로가 없다 |

## 매매 TR 은 조용히 틀린다 — 검증부터

수집 TR 은 필드명이 틀리면 컬럼이 통째로 None 이라 바로 보인다.
**잔고 TR 은 그렇지 않다.** 보유수량이 0 으로 읽히면 "미보유 → 신규 매수" 판단이
그대로 나간다.

```bash
python scripts/verify_trading_trs.py            # 조회계만 (읽기 전용)
python scripts/verify_trading_trs.py --order 005930   # 1주 매수까지
```

종목코드 정규화도 같은 이유다 — 키움 잔고는 `A005930` 처럼 접두어를 붙여 주는 경우가
있고, 그대로 두면 보유분을 못 알아봐 **이력 버퍼가 통째로 무력화된다**
(`broker._normalize_code`, `tests/test_broker.py::TestCodeNormalization`).


## 핵심 설계 원칙 — 생략 금지

"오를까/내릴까"뿐 아니라 **"지금 판단해도 되는가"까지 모델이 결정하게 한다.**
신뢰구간 폭 기반 기권 로직이 이 프로젝트의 핵심 차별점 중 하나다.

그래서 **기권 판단이 방향 판단보다 먼저 온다.** 순서를 바꾸지 말 것.

## 단일 구현 원칙 (절대)

백테스트가 쓰는 함수와 모의투자가 쓰는 함수는 **동일한 코드**여야 한다.
`signal.py` 하나만 사용하고 실행 경로별 분기를 만들지 않는다.

## 임계값 보정 — 절대값을 추측하지 말 것

**기권 임계값은 예측 폭 분포의 백분위로 잡는다** (`abstain.percentile`).

실측(2026-08-25): 데이터를 보기 전 추측한 절대값 0.05 로는 기권률 **95.8%**,
거래 **0건**이 나왔다. 5일 수익률의 자연 폭(q90-q10)이 0.124 라 0.05 는
"모델이 2.5배 확신해야 거래"라는 뜻이었다.
`percentile: 30` 으로 바꾸니 기권률이 의도대로 70% 가 됐다.

`resolve_abstain_threshold()` 가 백분위 → 절대값 변환을 담당한다.
백테스트는 예측 폭 분포를, 모의투자는 최근 예측 폭을 넣는다 — **같은 함수**다.

## 거래가 안 나올 때 보는 순서

0. **랭크 IC 의 t 값** — 2 미만이면 방향 예측력 자체가 없다.
   **매매 규칙을 아무리 손봐도 성과는 안 나온다** — 피처/타깃 설계로 돌아가야 한다.
   거래 로직을 통째로 우회한 지표라 여기서 먼저 갈린다 (`src/evaluation/CLAUDE.md`)
1. **평균 노출도 / 평균 보유종목** — 0 에 가까우면 성과 지표를 해석하지 말 것
2. **기권률** — 100% 에 가까우면 폭 임계값 문제
3. **q50 이 방향 임계값을 넘는 비율** — `absolute` 모드에서만 의미 있다.
   방향 임계값은 `max(설정값, 왕복비용 0.31%)` 로 강제되므로 비용보다 낮출 수 없다

`scripts/backtest.py` 가 위를 모두 로그와 리포트에 남긴다.

## 임계값은 확정값이 아니다

임계값과 포지션 사이징 공식의 정확한 수치는 처음부터 확정하지 않는다.
백테스트하면서 튜닝할 대상으로 취급한다. 현재 값은 `configs/config.yaml`의
`trading` 섹션에 있고, 전부 **잠정치**다.

단, 한 가지는 코드로 강제한다: **방향 임계값은 왕복 거래비용보다 작아질 수 없다**
(`generate_signal`이 `max()`로 강제). 이걸 풀면 수수료로 잃는 전략이 나온다.
