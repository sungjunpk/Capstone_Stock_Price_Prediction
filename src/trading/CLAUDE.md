# src/trading — 매매 신호·리스크·모의투자 실행

> 루트 [`CLAUDE.md`](../../CLAUDE.md)의 절대 규칙이 우선한다.
> **모의투자 전용이다. 실전매매가 아니다.**

## 자동매매 판단 기준

모델의 Quantile 출력(10/50/90분위)을 아래 **순서대로** 규칙화해 매매 신호로 변환한다.

```
1. [기권 판단] 90분위 - 10분위 신뢰구간 폭이 임계값보다 넓으면 → 거래 안 함, 관망
2. [방향 판단] `direction.mode` 가 정한다
   - cross_sectional (기본): 기권 통과분끼리 q50 순위 → 상위 top_n 매수
   - absolute: q50 이 고정 임계값 초과 시 매수. 임계값은 왕복비용 위로 강제
3. [포지션 사이징] 확신할수록(구간이 좁을수록) 크게. 균등 배분 아님
   - 선택된 종목들 사이에서 **정규화**해 목표 노출을 채운다(rank_normalized)
   - `exposure_scaling`: 생존 후보가 적으면 총 노출을 줄인다 → "얼마나 쉬는가"
4. [리스크 오버레이] 최종 주문 전 반드시 아래 안전장치를 적용
   - 개별 종목 보유비중 상한 (예: 전체 자산의 10% 이내)
   - 손절매(stop-loss): 진입가 대비 -N% 하락 시 강제 청산
   - 일일 최대 거래횟수 제한 (과적합 신호로 인한 과도거래 방지)
5. 최종 결정된 주문을 키움 REST API 모의투자 매수/매도 엔드포인트로 전송
```

## 절대 임계값을 버린 이유 (2026-08-25)

`absolute` 는 **예측 수준(level)이 국면과 어긋나면 그대로 무너진다.**
test 구간 실측:

| | |
|---|---|
| 모델 5일 예측 중앙값 | **-0.15%** |
| 같은 구간 실제 평균 | **약 +0.80%** |
| 매수 임계값 | +0.40% — 예측 90분위(+0.27%)보다 높다 |
| 결과 | 2.1년 동안 체결 **64건**, 평균 노출 8.9%. 진 게 아니라 참여를 안 했다 |

train 구간이 2022년 하락장을 포함해 끝나 모델이 그 시기의 드리프트를 학습했다.
**순위 방식은 모든 종목에 공통으로 낀 편차가 상쇄되므로 이 문제를 안 받는다.**
`tests/test_signal.py::test_level_shift_does_not_change_selection` 이 그 성질을 지킨다.

기권 로직은 그대로다 — 폭으로 거른 뒤 살아남은 것들만 순위를 매긴다.
**판단 순서(기권 → 방향)는 안 바뀌었다.**

## 총 익스포저 계산의 함정

`apply_risk_overlay` 의 `liquidate_unsignaled` 를 틀리게 잡으면 **곧 팔 종목을
'보유 중'으로 세어 신규 진입 비중을 깎는다.** 실측: 9종목 교체 매매에서
목표 0.81 이 0.09 로 잘렸다(9배). 매 회차 종목을 갈아타는 순위 방식에서 특히 치명적이다.

백테스트는 신호 없는 보유분을 청산하므로 `True` 가 맞다.
`tests/test_risk.py::test_rotation_does_not_shrink_new_positions` 가 회귀를 막는다.

⚠️ `top_n × max_position_pct` 가 `max_gross_exposure` 보다 작으면
노출 상한이 아니라 **종목 상한이 총 노출을 결정한다.** 설정 바꿀 때 같이 확인할 것.

## 핵심 설계 원칙 — 생략 금지

"오를까/내릴까"뿐 아니라 **"지금 판단해도 되는가"까지 모델이 결정하게 한다.**
신뢰구간 폭 기반 기권 로직이 이 프로젝트의 핵심 차별점 중 하나다.

그래서 **기권 판단이 방향 판단보다 먼저 온다.** 순서를 바꾸지 말 것.

## 단일 구현 원칙 (절대)

백테스트가 쓰는 함수와 모의투자가 쓰는 함수는 **동일한 코드**여야 한다.
`signal.py` 하나만 사용하고 실행 경로별 분기를 만들지 않는다.

## 임계값 보정 — 절대값을 추측하지 말 것

**기권 임계값은 예측 폭 분포의 백분위로 잡는다** (`abstain.percentile`).

실측(2026-08-25): 데이터를 보기 전 추측한 절대값 0.05 로는 기권률 **95.8%**,
거래 **0건**이 나왔다. 5일 수익률의 자연 폭(q90-q10)이 0.124 라 0.05 는
"모델이 2.5배 확신해야 거래"라는 뜻이었다.
`percentile: 30` 으로 바꾸니 기권률이 의도대로 70% 가 됐다.

`resolve_abstain_threshold()` 가 백분위 → 절대값 변환을 담당한다.
백테스트는 예측 폭 분포를, 모의투자는 최근 예측 폭을 넣는다 — **같은 함수**다.

## 거래가 안 나올 때 보는 순서

0. **랭크 IC 의 t 값** — 2 미만이면 방향 예측력 자체가 없다.
   **매매 규칙을 아무리 손봐도 성과는 안 나온다** — 피처/타깃 설계로 돌아가야 한다.
   거래 로직을 통째로 우회한 지표라 여기서 먼저 갈린다 (`src/evaluation/CLAUDE.md`)
1. **평균 노출도 / 평균 보유종목** — 0 에 가까우면 성과 지표를 해석하지 말 것
2. **기권률** — 100% 에 가까우면 폭 임계값 문제
3. **q50 이 방향 임계값을 넘는 비율** — `absolute` 모드에서만 의미 있다.
   방향 임계값은 `max(설정값, 왕복비용 0.31%)` 로 강제되므로 비용보다 낮출 수 없다

`scripts/backtest.py` 가 위를 모두 로그와 리포트에 남긴다.

## 임계값은 확정값이 아니다

임계값과 포지션 사이징 공식의 정확한 수치는 처음부터 확정하지 않는다.
백테스트하면서 튜닝할 대상으로 취급한다. 현재 값은 `configs/config.yaml`의
`trading` 섹션에 있고, 전부 **잠정치**다.

단, 한 가지는 코드로 강제한다: **방향 임계값은 왕복 거래비용보다 작아질 수 없다**
(`generate_signal`이 `max()`로 강제). 이걸 풀면 수수료로 잃는 전략이 나온다.
