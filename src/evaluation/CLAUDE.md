# src/evaluation — 평가·백테스트

> 루트 [`CLAUDE.md`](../../CLAUDE.md)의 절대 규칙이 우선한다.

## 평가 원칙

- **단순 방향 정확도로 평가하지 않는다.** 리스크 조정 지표 중심으로 본다
  — Sharpe / Sortino / Calmar / Max Drawdown / Hit Rate / Turnover
- **거래비용을 반영한 walk-forward 백테스트**가 최종 근거다
  — ⚠️ **아직 미구현이다.** `split.walk_forward_windows()` 는 있지만 부르는 곳이 없고,
  현재 백테스트는 고정 split 의 test 한 구간(2024-07~2026-08)만 돈다. 그 구간이
  역사적 폭등장 하나뿐이라는 게 지금 가장 큰 미해결 약점이다(README '다음 할 일' 22번)
- 방향 정확도는 보조 지표로만 인용한다

## 성과보다 먼저 읽는 것 — 예측력 진단

성과 지표는 **모델의 예측력과 매매 규칙이 섞인 결과**다. 둘을 분리하지 않으면
"모델이 못 맞힌 것"과 "거래 규칙이 막은 것"을 구분할 수 없다.
`metrics.py` 의 두 함수가 거래 로직을 통째로 우회해 예측력만 직접 잰다.

| 지표 | 묻는 것 |
|---|---|
| `rank_ic` | 같은 날 종목들 사이에서 **순위를 맞히는가** (날짜별 Spearman) |
| `decile_spread` | 상위 10% − 하위 10% 수익 차이 = **실제로 먹을 수 있는 폭** |

**판정 순서:**

1. `t_stat` < 2 → 방향 예측력 없음. **매매 규칙을 손봐도 성과는 안 나온다**
2. `spread_mean` ≤ 왕복비용(0.31%) → 순위는 맞히지만 매매로 못 옮긴다
3. 둘 다 통과해야 성과 지표를 해석할 가치가 있다
4. **순열검정(음성 대조군)** — 통과했더라도 성과가 신호에서 왔는지는 별개다

### 4번을 반드시 본다 (2026-08-31 에 배웠다)

`q50` **순위만** 날짜별로 섞고 나머지(폭·기권·top_n·버퍼·비용)를 그대로 둔 채
백테스트를 다시 돌린다. 바뀌는 것이 순서 하나뿐이므로, 실제 성과와 섞은 성과의
차이가 **신호의 기여분**이다. `scripts/gbdt_baseline.py --permutations N` 이 한다.

실측: Phase1 의 Sharpe 1.63 은 섞었을 때 평균 1.51 (범위 1.13~1.88, **p=0.25**).
**신호 기여는 Sharpe +0.12 이고 유의하지 않다.** 성과의 대부분은 기권이 만든
저변동성 편향과 낮은 회전율에서 나왔다. GBDT 는 섞은 쪽이 더 좋았다(p=1.00).

⚠️ 그래서 **랭크 IC 가 유의하다는 것만으로 "모델이 성과를 만들었다"고 쓰지 않는다.**
IC 는 전체 횡단면의 순서를 재는데 전략은 상위 `top_n` 개만 산다 — 개선이 중간·하위에서
나면 전략이 만질 수 없다. 앙상블이 IC 를 19% 올리고도 백테스트가 제자리였던 것과
같은 구조다. 상세는 README 의 "2026-08-31 GBDT 베이스라인 + 순열검정".

⚠️ **날짜 단위로 먼저 집계한다.** 전체를 한 번에 상관계수 내면 같은 날 146종목이
시장 공통 요인으로 묶여 있어 유효 표본이 부풀고 유의성이 과대평가된다
(스윕에서 블록 부트스트랩을 쓴 것과 같은 이유).

⚠️ 실현 수익률을 쓰지만 **사후 평가 전용**이다. 매매 판단에 들어가면 look-ahead 다.

## 배경 — 2026-08-25 test 구간에서 배운 것

피처 중요도 상위 5개가 전부 변동성 계열(`bb_width`, `rvol_20`, `atr` …)이었고,
예측의 분산이 어디 있는지 보면:

| | p10 → p90 | 폭 |
|---|---|---|
| q50 (방향) | −0.44% → +0.27% | **0.7%p** |
| 구간폭 (변동성) | 9.2% → 26.6% | **17.4%p** |

**구간폭은 25배 넓게 조절하면서 중앙값은 거의 안 움직였다.**
pinball loss 개선(+3.34%, 2.8σ)의 대부분이 변동성 예측에서 나왔다는 뜻이다.
변동성은 군집성 때문에 원래 예측 가능하고 방향은 아니다.

**통계적 유의성이 경제적 유의성을 뜻하지 않는다.** 랭크 IC 는 그 둘을 갈라놓기 위한 장치다.

## 서술 톤 (보고서 작성 시)

**"하락장에서도 이긴다"는 프레이밍은 지양한다.** 리스크 조정 성과로 서술할 것.
과적합된 백테스트는 어떤 구간에서든 좋아 보이게 만들 수 있다 —
walk-forward와 거래비용이 그 방어선이다.

## 백테스트 설정

`configs/config.yaml`의 `backtest` 섹션이 단일 소스:

- walk-forward 창: train 36개월 / val 6개월 / test 6개월, 6개월씩 이동
  (`backtest.walk_forward` — 값은 정해져 있지만 **아직 이 창으로 도는 코드가 없다**)
- 초기 자본 1억
- 거래비용: 수수료 1.5bp(편도) + 거래세 18bp(매도) + 슬리피지 5bp

## 절대 규칙

백테스트가 쓰는 신호 생성 함수는 모의투자가 쓰는 것과 **동일한 코드**여야 한다.
`src/trading/signal.py` 하나만 사용하고, 백테스트/실행 분기를 만들지 않는다.
이게 깨지면 "백테스트는 좋은데 실전은 다르다"의 원인이 된다.

## 규칙 비교는 한 세션에서 — `--compare`

```bash
python scripts/backtest.py --compare
```

예측(체크포인트 로드 + 75k 샘플 추론, 약 7초)은 **한 번만** 계산하고 규칙만 갈아끼운다.
변형당 백테스트는 1초라 5개를 더해도 총 시간이 거의 그대로다.
변형 목록은 `scripts/backtest.py` 의 `RULE_VARIANTS` 하나가 단일 소스다.

각 변형은 `outputs/reports/` 에 개별 JSON 으로 남는다(덮어쓰지 않는다).

**부수 효과**: 캐글 노트북의 백테스트 셀이 이 한 줄로 고정된다.
규칙을 바꿔도 노트북을 다시 Import 할 필요 없이 **재시작만** 하면 된다
(클론 셀이 저장소를 새로 받으므로).

## 추정하지 말고 측정한다

리포트에 다음이 실측으로 남는다. 회전율 × 단가로 추정하던 것들이다.

| 항목 | 왜 |
|---|---|
| `annual_cost_pct` / `total_cost_pct` | 실제 지불한 거래비용. 추정 연 7%가 맞았는지 확인 |
| `avg_holding_days` | 이력 버퍼가 먹혔는지 가장 직관적인 숫자 |
| `blocked_by_reason` | 손절/익절/거래한도/공매도불가 — **발생 지점에서 센다** |

`blocked_by_reason` 은 문자열을 파싱하지 않는다. 파싱하면 메시지 문구를 바꾸는 순간
조용히 깨진다 (`src/trading/risk.py` 의 `_block()`).

## 결과 보관
