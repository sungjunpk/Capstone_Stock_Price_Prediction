# src/webapp — 결과 대시보드

> 루트 [`CLAUDE.md`](../../CLAUDE.md)의 절대 규칙이 우선한다.

## 무엇인가

모의투자 실행 결과 · 백테스트 성과 · 모델 해석을 한 화면에서 보는 로컬 웹 페이지.

```bash
python scripts/dashboard.py            # http://127.0.0.1:8765
python scripts/dashboard.py --build    # 정적 HTML 한 장 (서버 없이 열린다)
```

## 규칙 셋 — 이걸 어기면 대시보드가 문제의 원인이 된다

**1. 읽기 전용이다.** 화면에서 주문을 낼 수 있게 만들지 않는다.
버튼 하나로 실주문이 나가는 경로를 브라우저에 열어두면, 이 프로젝트에서 제일
되돌릴 수 없는 동작이 제일 누르기 쉬운 곳에 놓인다.
주문은 `scripts/paper_trade.py --execute` 한 곳에서만 나간다.

**2. 여기서 계산하지 않는다.** 지표는 백테스트가, 예측은 추론이, 주문은 실행기가
이미 `outputs/` 에 남긴 값이다. 대시보드가 자기 식으로 다시 계산하면
화면과 리포트가 서로 다른 말을 하고, 어느 쪽이 맞는지 알 수 없게 된다.
`collect.py` 는 **읽고, 고르고, 정리만** 한다.

**3. 의존성을 추가하지 않는다.** 표준 라이브러리 `http.server` 와 문자열 템플릿뿐이다.
차트도 CSS 와 인라인 SVG 로 그린다. 학습·수집 파이프라인이 웹 프레임워크나
프런트엔드 빌드 때문에 깨지는 일이 없어야 한다.

**4. 기본 바인딩은 127.0.0.1.** 계좌 상태가 보이는 화면이다.

## 화면 순서 = 판단 순서

오늘의 판단 → 신호 상세(기권/순위) → 보유 → 백테스트 → 규칙 비교 → 모델 → 실행 이력.

기권이 방향보다 먼저 오는 프로젝트 원칙이 화면에도 그대로 보이게 둔다.

## 없는 데이터로도 죽지 않아야 한다

대시보드는 파이프라인의 곁가지라, 리포트가 하나 비었다고 예외가 나면
정작 결과를 봐야 할 때 못 본다. `tests/test_webapp.py` 가 빈 상태·부분 상태를 먼저 본다.

## 조용히 틀리는 자리 둘 (실측으로 잡았다)

| 함정 | 증상 | 방어 |
|---|---|---|
| 같은 세션의 옛 실행을 대표로 고름 | 화면에 Sharpe 0.00 이 뜬다 | `latest_backtests` 가 **가장 최근** 것을 고른다 |
| 캐글 학습이라 로컬에 실제 리포트가 없음 | smoke 숫자를 학습 성과로 읽는다 | `_smoke` 플래그 + 화면 경고, 체크포인트 불일치도 경고 |

## 파일

| 파일 | 역할 |
|---|---|
| `collect.py` | `outputs/` 에서 그릴 데이터를 모은다 (계산 없음) |
| `render.py` | HTML 생성. 외부 텍스트는 전부 `escape` |
| `server.py` | stdlib 서버. 요청마다 다시 읽어 렌더링한다 |
